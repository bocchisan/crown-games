# auction — CLAUDE.md

Игра класса B на форме `two-outcome`. Раньше — единственная «зрячая» игра; после харденинга чейн не читает,
вместо `getAccountInfo` — пруф рождения.

Контракт игр — `crown-spec/docs/games-harness.md`. Строгость/глоссарий — `crown-spec/CLAUDE.md`.
Спека — `docs/spec.md`; план — `docs/build-plan.md`.

Специфика:
- **Лот = конкурсная/голосовательная группа, `B` = вкладов в лоте** (каждый доливший — своя репутация).
  **Область расчёта (resolver) = вклад:** `resolver = key([entry_id])`, `entry_id = sha256(lot_id ‖ donor ‖ nonce ‖ gross ‖ deadline)` —
  прообраз обязан коммитить **все** поля соли эскроу, иначе два эскроу делят одну область (спека §Идентификаторы).
  Из-за `return_entry` исходы вкладов лота расходятся, поэтому резолвер живёт на листе, не на лоте — иначе
  settle одного клеймил бы соседа.
- **Победителя называет получатель** (`pick_winner` из принятых лотов) — ончейн-скана «кто дороже» нет.
  «Самый дорогой» — рекомендация борда `crown-app`, не ончейн-правило. Никакой пагинации/курсора/таймера:
  во всей системе больше нет ограниченных итераций.
- Двухступенчатый борд: «заявлено» (пруф истории, **вне канистры** — слой crown-app) vs «подтверждено»
  (пруф рождения). Отсечка `T = created_at+duration` — граница приёма пруфов (окно `Bidding`).
- Застрявший аукцион деньги не держит: не выбрали/не отменили → каждый эскроу выходит `refund()` по
  `deadline` (единственная safety, как везде).
- **Доверие к индексу расщеплено** (инвариант харнесса, `P6.6`): BLS сертификата — разово, на платном
  `push_root`; на границе — только обход хеш-дерева, и для пруфа рождения (`register_entry`), и для
  пруфа веса (`vote`). Иначе прямой ingress не влезает в 200M `inspect_message`. `certified_root` —
  ровно одно вхождение, в `push_root` (гейт CI). Политика кеша (глубина, вытеснение, проверка против
  любого корня) — **не здесь**, а в `crown-games-common::roots`, один источник на все игры; локально
  живёт только сам `ROOTS` как состояние канистры.
- **Общее — в `crown-games-common`, не здесь.** Кроме крипты туда с `P7.6` переехали хранилище
  подписи вердикта (`signing`, инвариант #5), `chain_id` (ключ книги — обязан совпадать с индексом),
  разбор полей запроса, `MAX_ARG_BYTES`/`V_MAX` и чтение `config/` на бейке. В игре остаётся её
  собственное: прообраз `scope_id`, формулировки подписываемых сообщений, машина и вердикт.
