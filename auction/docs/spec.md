# auction — Спека

Игра класса B на форме `two-outcome`. Получатель открывает аукцион на `duration`. Зрители ставят: каждый
кладёт деньги в **свой** эскроу + прикладывает текст-условие. Текст сначала виден только получателю;
принял (`accept_lot`) — текст раскрыт, лот в торгах; в принятый лот можно **доливать** (новый эскроу к
тому же `text_hash`). Окно закрылось — **получатель выбирает победивший лот** (`pick_winner`) из принятых;
остальным — возврат. Дальше как в tasks: получатель выполняет за `perform_window`, `ready`, голосование,
исход. **Лот = конкурсная/голосовательная группа; область расчёта = вклад** (`resolver = key([entry_id])`).

Общие инварианты — `crown-spec/docs/games-harness.md`; здесь — вся специфика аукциона, дословно.

## Идентификаторы, резолвер, набор эскроу

- `auction_id = sha256("crown:auction" ‖ u8(len(canister_id)) ‖ canister_id ‖ recipient(32) ‖
  u64le(recipient_nonce) ‖ u64le(duration) ‖ u64le(perform_window) ‖ u64le(voting_period) ‖ u64le(min_entry))`
  — свободный, конфиг в прообразе.
- **Лот — конкурсная группа**: `lot_id = sha256(auction_id ‖ text_hash)`. По `lot_id` идут `accept_lot`,
  `return_lot`, `vote`, `pick_winner`. Лот **не** несёт резолвера — только группирует вклады с общим
  условием (`text_hash`) для приёма, голоса и выбора победителя.
- **Вклад — единица расчёта**: `entry_id = sha256(lot_id ‖ donor(32) ‖ u64le(nonce))`,
  `resolver = key([entry_id])`. У каждого эскроу **свой** резолвер. Эскроу транзитивно коммитит к таймингам
  через `resolver → entry_id → lot_id → auction_id`.
- **Почему резолвер на вкладе, а не на лоте.** `return_entry` разводит исходы вкладов одного лота
  (возвращённый → `Cancel`, прочие → исход лота). Общий резолвер лота дал бы **одну** подпись на всех — и
  возвращённый вклад смог бы клеймить `settle` вместе с соседями. Резолвер-на-листе: у каждого эскроу своя
  подпись и свой исход. Цена: подпись **не** амортизируется на лот (каждый эскроу платит за свою). Это
  сознательный размен корректности на стоимость.
- **Набор эскроу на лот** (не один): долив = новое рождение под тот же `text_hash` (свой `entry_id` и
  резолвер), чтобы каждый доливающий получил репутацию за свой вклад.

## Состояния

`Bidding` · `Performing{winner_lot: [u8;32]}` · `Voting{started_at:u64}` · `Done{winner: opt Outcome}`.
`Outcome ∈ {Settle, Cancel}`. `Done{winner:null}` = победителя не было (`cancel_auction`, либо окно
закрылось и получатель никого не выбрал — деньги выходят `refund()` по `deadline`).

Границы времени (применяются **до** действия, `checked`):
- `Performing → Done{Cancel}` при `now ≥ created_at + duration + perform_window` (получатель не успел `ready`).
- `Voting → Done{verdict(votes)}` при `now ≥ started_at + voting_period`.
- `Bidding` **не** имеет временного перехода: окно приёма закрывается на `T = created_at + duration` (гейт
  в самих `register_entry`/`accept_lot`/`return_*`), но состояние остаётся `Bidding`, пока получатель не
  вызовет `pick_winner` (→ `Performing`) или `cancel_auction` (→ `Done{null}`). Никакого таймера/скана —
  застрявший аукцион деньги не держит: каждый эскроу выходит `refund()` по своему `deadline` (единственная
  safety, как во всей системе).

`Done` — поглощающее. `created_at` — слот рождения первого подтверждённого вклада (слот→время по пиннутой
`SLOTS_PER_SECOND`, как в `conditional-funding`), фиксируется при материализации.

**Лот** (поля, не enum): `accepted_at: opt`, `returned: opt`, `text_hash`, вклады. Роли: незарегистрирован ·
зарегистрирован-непринят · принят (`accepted_at≠null`) · возвращён (`returned≠null`) · победитель
(`auction.winner_lot == lot_id`). Побеждать может только принятый (`accepted_at≠null ∧ returned=null`).

**Вклад:** `seq: u64` (монотонный, полный порядок), `returned: opt`, `gross`, `escrow`, `entry_id`.

## Таблица переходов

Время применяется первым; провалившееся из-за сдвига времени действие всё равно персистит наступивший переход.

| Метод | Bidding (`now < T`) | Bidding (`now ≥ T`) | Performing | Voting | Done |
|---|---|---|---|---|---|
| `create_auction`¹ | — | — | — | — | — |
| `get_resolver` | OK (query, в любом состоянии) | | | | |
| `register_entry` | OK (`gross≥min_entry`, `deadline≥floor`, лот не возвращён, пруф рождения) | ✗ | ✗ | ✗ | ✗ |
| `accept_lot` | OK (лот есть, не принят, не возвращён) | ✗ | ✗ | ✗ | ✗ |
| `return_lot` (не победитель) | OK → лот `returned` | ✗ | ✗ | ✗ | ✗ |
| `return_lot` (победитель) | — | — | OK → `Done{Cancel}` | ✗ | ✗ |
| `return_entry` (winner-лот) | OK | OK | OK | ✗ | ✗ |
| `return_entry` (не winner-лот) | OK | OK | ✗ (проигравший лот и так `Cancel`) | ✗ | ✗ |
| `pick_winner(lot)` | OK → `Performing{lot}` (лот принят ∧ не возвращён) | OK → `Performing{lot}` (то же) | ✗ | ✗ | ✗ |
| `cancel_auction` | OK → `Done{null}` | OK → `Done{null}` | ✗ | ✗ | ✗ |
| `ready` | ✗ | ✗ | OK → `Voting{now}` | ✗ | ✗ |
| `vote` | ✗ | ✗ | ✗ | OK (порядок: подпись→время→дедуп `(lot_id,voter)`→вес; `weight≥MIN_VOTE_WEIGHT`) | ✗ |
| `request_signature` | «нет вердикта» | «нет вердикта» | по `resolve` | по `resolve` | по `resolve` |

Приём заморожен на `T = created_at+duration` (`register_entry`/`accept_lot`/`return_*` при `now ≥ T` — ✗),
но `pick_winner`/`cancel_auction` остаются доступны получателю, пока аукцион в `Bidding`. `return_entry`
винтер-лота живёт и после выбора победителя (в `Performing`).

¹ `create_auction` — чистая деривация `auction_id`, пишет ноль (ленивое создание, permissionless);
материализация — на **первом подтверждённом вкладе**, где хеш-проверяются `duration/perform_window/
voting_period/min_entry` из прообраза и валидируются диапазоны (`[MIN_DURATION,MAX_DURATION]`). Контроль
получателя (`accept`/`return`/`pick_winner`/`cancel`/`ready`) — signature-gated по `recipient` из прообраза.
`pick_winner`/`cancel`/`ready` самоподписаны, пруфа рождения не несут и **не** материализуют.

## Выбор победителя (получателем)

Победителя **называет получатель** — `pick_winner(lot)` над принятым (`accepted_at≠null`) не возвращённым
лотом переводит аукцион в `Performing{winner_lot}`. Ончейн-скана «кто дороже» **нет**: получатель и так
курирует конкурс (`accept_lot` выборочно, `return_lot` кого угодно — соревнуются только принятые им лоты),
поэтому выбор победителя — естественное продолжение этой дискреции, а не отдельная вычислительная стадия.

«Самая дорогая ставка» — **рекомендация** борда (слой `crown-app`, `§Двухступенчатый борд`), а не
ончейн-энфорсд правило: канистра не суммирует и не сравнивает лоты, никакой ограниченной итерации по ним.
Размен осознанный — небольшая дополнительная дискреция получателя (который и так фильтрует принятые лоты) в
обмен на радикально более простую и дешёвую канистру.

## Трёхступенчатое разрешение (`request_signature`, per-entry)

`request_signature(chain, auction, lot, escrow)` разрешает **конкретный вклад** (по его `escrow`) и
подписывает вердикт ключом `key([entry_id])` этого вклада:

1. вклад известен и `returned≠null` → `Cancel`;
2. иначе лот известен и `returned≠null` → `Cancel`;
3. иначе, `winner = (auction.winner_lot == lot_id)`:
   - `Done{outcome}`: победитель→`outcome`; иначе→`Cancel`;
   - `Performing`/`Voting`: победитель→«нет вердикта»; проигравший→`Cancel`;
   - `Bidding`: «нет вердикта» (победитель ещё не выбран).

Незнакомый вклад (`entry=null`) разрешается только ступенью 3 (`Cancel`, т.к. его лот не победитель, либо
после `Done`). Ретрай пере-подписывает тот же вердикт. Оплаченный pull: оплата принимается только когда есть
вердикт (не «нет вердикта»), до `sign_with_schnorr`.

## Двухступенчатый борд

- **«заявлено»** — пруф истории кошелька; проверяется бесплатно; на доску сразу; **вне канистры** (слой
  `crown-app`, в периметре не хранится); на выбор победителя **не влияет**.
- **«подтверждено»** — пруф рождения эскроу; только подтверждённые вклады существуют для канистры.
  `register_entry` не читает чейн → **пруф рождения** (свидетель против корня рождений, локально).
- Пруф несёт **слот рождения** → подтвердить можно задним числом в окне приёма. **Отсечка `T`**:
  `T = created_at + duration` — граница приёма (`register_entry` при `now ≥ T` отбит гейтом). Пруф вклада
  засчитывается, только если подан до `T`. Внешняя граница жизни эскроу — `deadline`. Пруф доказывает факт
  рождения, **не** live-`closed`; на мёртвость/возврат полагаемся через `deadline`/`refund()`, а не
  live-чтение (его нет).

## Правило дедлайна

`deadline ≥ created_at + duration + perform_window + voting_period + DEADLINE_MARGIN`; все сложения
`checked`, переполнение → ошибка (не пропуск); граница включительна. Проверяется при `register_entry`.

## Константы

| Константа | Значение |
|---|---|
| `MIN_VOTE_WEIGHT` | `100_000` |
| `MIN_DURATION` | `60` (1 мин) |
| `MAX_DURATION` | `2_592_000` (30 сут) |
| `DEADLINE_MARGIN` | `259_200` (72 ч) |
| `V_MAX` | `500` — кэп голосов на аукцион |
| `LOGIC_VERSION` | `1` (первая версия по текущей спеке); пиннуется тестом на неизменность |
| `min_entry` | поле прообраза (`0` = только флор формы) |
| `voting_period`/`perform_window` | поля прообраза, диапазон `[MIN_DURATION, MAX_DURATION]` |

## Вердикт-сообщение и деньги

**Подпись вклада** `key([entry_id])` над `"crown:two-outcome:<cluster>" ‖ program_id(32) ‖ u8(outcome)`
(`settle=0, cancel=1`); проверяется on-chain против поля `resolver` эскроу. Одна подпись — один вклад
(без корня/пути). Разные вклады лота (в т.ч. возвращённые) подписываются независимо.

`Settle` (0): эскроу → комиссия `fee_bps` → `fee_wallet`; `gross−fee` → получатель; `Settled(payer=escrow)`;
репутация донору = `gross−fee`. Только здесь. `Cancel` (1): 100% донору, ни `Settled`/комиссии/репутации.
`refund()` после `deadline`: донору, без подписи, мимо книги.

## Методы (`.did`, фиксирован)

`create_auction` · `get_resolver` (query) · `register_entry` · `accept_lot` · `return_lot` · `return_entry`
· `pick_winner` · `cancel_auction` · `ready` · `vote` · `request_signature(chain, auction, lot, escrow)` ·
queries (`get_auction`, `get_lot`, `get_logic_version`) · инфра `init(opt InitArgs)`/`bootstrap()`.
`get_resolver(lot, donor, nonce)` считает `entry_id = sha256(lot_id ‖ donor ‖ nonce)` и возвращает
`key([entry_id])`. Голос — валидность в `inspect_message`, дедуп `(lot_id, voter)`, кэп `V_MAX`.

**Граница (`inspect_message`, харнесс §6):** каждый меняющий состояние вызов доказывает применимость до
раунда — `register_entry` пруфом рождения (дорогая BLS не идёт реплицируемо на мусор), действия получателя
(`accept_lot`/`return_lot`/`return_entry`/`pick_winner`/`cancel_auction`/`ready`) — подписант ≡ получатель +
состояние допускает, `vote` пруф веса + порог. Обречённое отбивается не-реплицируемо; `update` авторитетен.

Query состояния игры **не сертифицированы** (`+witness` снят): доверие в Crown течёт через threshold-подпись
резолвера (проверяется on-chain) и сертифицированные пруфы **индекса** (книга/рождения), а не через состояние
канистры-игры — деньги эскроу клеймит против подписи, не против query.

## Крайние случаи

- `accept` уже принятого → ✗. `return_lot` — только в `Bidding` для не-победителя; после выбора — только
  победитель в `Performing` (→ `Done{Cancel}`).
- Долив в непринятый лот разрешён (непринятый не может быть выбран); долив в возвращённый лот → ✗.
- Получатель не выбрал и не отменил → аукцион стоит в `Bidding`; каждый эскроу выходит `refund()` по
  `deadline`. `cancel_auction` → `Done{null}`, всем `Cancel` сразу.
- Победитель, вклады которого частично возвращены (`return_entry`): каждый возвращённый вклад лично
  разрешается `Cancel` (ступень 1), живые — исходом лота. Именно ради этого резолвер на вкладе.
- Escrow, рождённый до `T`, но пруф подан позже (в окне) — засчитывается; после `T` — нет (`refund()`).
- Непруфнутый/незнакомый escrow: ступень 3 (`Cancel` как непобедитель) либо `refund()`.
- «заявлено» никогда не влияет на исход — только «подтверждённые» (пруф рождения) до `T`; победителя выбирает
  получатель.

## DoD / тесты (`crown-spec/docs/01-standards.md §Тесты 8,9,12`)

`logic/` zero-dep: машина `Bidding→Performing→Voting→Done` (границы окон точные, `Overflow` не двигает
состояние, `Done` поглощающее, `pick_winner` только из `Bidding` по принятому лоту), вердикт голоса
(two-outcome, строгое большинство), правило дедлайна (checked, включительна), трёхступенчатое разрешение
`resolve` per-entry. Не читает сети (grep). `register_entry` — пруф рождения, не RPC; без пруфа ноль записи;
приём заморожен на `T`. Победителя называет получатель (`pick_winner`) — канистра лоты не суммирует и не
сканирует. Подпись `key([entry_id])` против `resolver` эскроу; возвращённый вклад лота разрешается
`Cancel` независимо. Граница: обречённый вызов (плохой пруф рождения/веса, не тот подписант) отбит в
`inspect_message`, до реплицируемого `update`; голос — дедуп `(lot_id, voter)`, кэп `V_MAX`. E2e через
реальную сеть.
