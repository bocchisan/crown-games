# subscription — Спека

Использование формы `stream` (`crown-factory`) как **предоплаченной рассрочки**: один донор кладёт
`chunk × n_chunks` в **один** эскроу по **одной** строке распределения (до `K_MAX=6` получателей на
кусок); куски выдаются **строго по порядку и по расписанию** — `release(k)` **permissionless**, как
только `now ≥ t0 + k·period`. Отмена — подпись донора; заглохший поток → возврат остатка донору по
просрочке. Крауда, голосования, резолвера, threshold-ключа и канистры **нет** — 1:1, детерминированное
расписание. Выплата каждого куска идёт **через сплиттер** (единая точка), `Settled(donor=escrow)` →
репутация донору по атрибуции индекса.

Ончейн-детали формы `stream` — **канон здесь** (подписка её единственный потребитель);
`crown-factory/docs/spec.md` держит лишь контракт формы и на этот файл ссылается. Периметр не
трогается: подписи резолвера, оплаченного pull'а и канистры у подписки нет.

## Идентификатор, адрес

- **Область не выделяется** (резолвера нет): подписка = один эскроу формы `stream`.
- **Адрес эскроу** = `crown_derive::solana_pda_address(factory, [b"escrow", salt]).0`, где
  `salt = crown_salt::stream(donor, K, recipients[K], shares[K], chunk, n_chunks, t0, period, fee_bps, fee_wallet, nonce)`.
  Резолвера в соли нет.

## Состояние (ончейн, форма `stream`) — канистры нет

Всё состояние держит аккаунт эскроу (`crown-factory §stream`): `released: u16` (курсор порядка),
`settled: bool` (терминальность), поля рождения (нотаризованы адресом, неизменны). Логически:
`remainder = (n_chunks − released)·chunk`; поток жив, пока `!settled ∧ released < n_chunks`.

## Действия → результат

| Действие | Кто | Гейт (форма, ончейн) | Результат | Терминально |
|---|---|---|---|---|
| **create_escrow** («подписаться») | донор (подписант) | валидация формы при рождении | один эскроу, наполнен `gross = chunk·n_chunks` | нет |
| **release(k)** | **кто угодно** (газ) | `!settled ∧ k == released ∧ now ≥ t0+k·period` (Clock) — **без подписи** | кусок распределён (ниже); `released += 1`; последний → `settled`, закрывает ATA (рента ATA → донору) | на последнем `k` |
| **cancel(sig)** | кто угодно относит подпись донора | подпись **донора** (ed25519-инструкция) против поля `donor` эскроу ∧ `!settled` | весь остаток → донору | **да** |
| **refund()** | кто угодно | `!settled ∧ now > t0 + released·period + RELEASE_MARGIN` — **без подписи** | весь остаток → донору | **да** |

Оплаченного pull'а, канистры и threshold-подписи нет: **расписание — это и есть авторизация выпуска**.

## Закон расписания (форма, ончейн)

```
due(t0, period, k) = t0 + k·period            // checked; выход за i64 → ошибка, не паника
release(k) валиден ⇔ now ≥ due(t0, period, k)  // границы включительны (now == due — созрел)
```
Порядок кусков держит **форма**: `release` не в свой черёд (`k ≠ released`) ревертит; `k ≥ n_chunks` не
исполнится никогда; повтор невозможен (`released` только растёт).

## Распределение куска (одна строка, `K_MAX=6`)

На `release(k)`:
- `piece_j = chunk · share_j / 10000` (пол); `fee_j = piece_j · fee_bps / 10000` (пол).
- `splitter.donate(recipient_j, piece_j − fee_j)` (CPI, authority — PDA) → `Settled(donor=escrow)` →
  **репутация донору**.
- Σ комиссий строки — **одним** переводом на ATA `fee_wallet` (мимо сплиттера, без события/репутации).
- «Пыль» `chunk − Σ piece_j` → донору, без комиссии.
- Точный баланс: `Σ через сплиттер + Σ комиссий + Σ пыли + возврат == gross`.
- Строка: `1 ≤ K ≤ 6` уникальных кошельков, `Σ shares ≤ 10000`, ≥1 ненулевая доля, каждый ненулевой
  `piece ≥ MIN_GROSS`. Получатели/доли позиционны — перестановка = другой адрес.
- `K` ATA получателей едут как `remaining_accounts` в порядке строки. Форма проверяет каждую **сама**:
  владелец-программа (`spl_token`), владелец ≡ получатель строки, минт — до CPI. Распаковка байтов
  (`try_deserialize`) владельца-программу не проверяет, а полагаться на то, что подставной аккаунт отобьёт
  сплиттер уровнем ниже, форме нельзя (`crown-factory/docs/spec.md` §Конвенция заголовка, п. 9).

## Отмена: подпись донора (ончейн)

Донор авторизует отмену Ed25519-подписью кошелька над сообщением формы; едет инструкцией
`ed25519_program` непосредственно перед `cancel`; форма проверяет её против поля `donor` эскроу:
```
cancel: DOMAIN_form ‖ program_id(32) ‖ escrow(32) ‖ 0x01
```
`DOMAIN_form = "crown:stream:<cluster>"`, `CANCEL_TAG = 0x01`. Подмена `donor` → другой `salt` → другой
адрес → cancel неисполним. Привязка к `(cluster, program_id, escrow)` — между кластерами/программами/
эскроу не переносится. Повтор безвреден (терминальность ончейн).

## Константы

| Константа | Значение | Пометка |
|---|---|---|
| `K_MAX` (`MAX_RECIPIENTS`) | `6` | строка распределения |
| строк (stream) | `1` | одна строка |
| `CANCEL_TAG` | `0x01` | заморожен |
| `DOMAIN_form` | `crown:stream:<cluster>` | форма |
| `fee_bps` / `fee_wallet` | `300` (devnet) / кошелёк; инвариант `< 10000` | |
| `period` / `n_chunks` / `gross` | `> 0` / `≥ 1` / `= chunk·n_chunks` | |
| `RELEASE_MARGIN` | `259_200` (72 ч) — **константа программы** формы (`shapes/stream/solana/src/lib.rs`), не поле `deploy/`: зазор до `refund()` после просрочки выпуска, по конвенции `DEADLINE_MARGIN` | |
| `MIN_GROSS` | `200_000` — тоже **константа программы**; минимальный ненулевой `piece` в строке, равен индексному флору пыли | |
| break-even | ~$0.20/выпуск (n=12, без подписи), +`MARGIN` 20% ~$0.24 (`cost.md §3`) | |

Из `crown-factory/deploy/<профиль>.toml` форма берёт только сетевое: `usdc` → `USDC_MINT`,
`splitter` → `SPLITTER`, `[domain].stream` → `CANCEL_DOMAIN`. Всё остальное вшито в байткод — менять
их значит менять программу, а не профиль.

`salt = sha256(donor32 ‖ u8(K) ‖ recipients K·32 ‖ shares K·u16le ‖ u64le(chunk) ‖ u16le(n_chunks) ‖
i64le(t0) ‖ i64le(period) ‖ u16le(fee_bps) ‖ fee_wallet32 ‖ u64le(nonce))` (резолвера нет; см. `crown-factory`).

## Деньги / репутация / комиссия по действиям

| | release | cancel | refund |
|---|---|---|---|
| Деньги | получателям через сплиттер (минус комиссия); пыль → донору | весь остаток → донору | весь остаток → донору |
| Репутация | **донору** (`+Σ piece` выпущенного) | нет | нет |
| Комиссия | `Σ fee_j` → `fee_wallet` | нет | нет |
| `Settled` | да (до K на tx) | нет | нет |

Репутация и комиссия — **только на `release`**. Голосования, `MIN_VOTE_WEIGHT`, `V_MAX`, кворумов,
резолвера нет.

## Экономика (детерминированное расписание → без `s`)

Выпуск не требует threshold-подписи (расписание проверяет форма) → член `s` из break-even уходит.
Стоимость на выпуск ≈ `g·(1 + 1/n)` (впись сеттлмента + амортизированная впись рождения);
break-even ≈ **$0.20/выпуск** (n=12), флор при `MARGIN` 20% ≈ **$0.24** (`cost.md §3`). Подписка
переходит из дорогого тира (был $1.39 с подписью) в дешёвый.

## Крайние случаи

- `release` не по порядку → форма ждёт `k == released` (реверт); `release` после `cancel`/`settled` →
  реверт; `refund()` до просрочки → реверт (`StreamAlive`).
- `donor == recipient` допустимо; program-owned получатель → `release` ревертит, выход через
  `cancel`/`refund()`.
- `k ≥ n_chunks` / поля несуществующего эскроу → `release` ревертит (гейт формы); ничего не тратится.
- Донор с несколькими эскроу отменяет каждый отдельно; часы формы (кластер) — единственные; раньше
  ончейн-срока `release` не исполнится.
- Гонка `cancel`↔`release` созревшего куска: если кусок созрел и ещё не выпущен, любой может `release`
  его получателю (штатно); `cancel` останавливает **будущие** куски и возвращает остаток.

## DoD / тесты (`crown-spec/docs/01-standards.md §Тесты 9,12`)

Форма `stream` (`crown-factory`): `due`/порядок кусков checked (overflow → ошибка, не паника), границы
включительны, монотонность по времени/`released`. `release` permissionless по расписанию, **без подписи**;
не в свой черёд/после терминала — реверт. `cancel` — подпись донора против поля `donor` (подмена → адрес
не тот → неисполнимо); текст сообщения пиннут. `refund()` без подписи после `RELEASE_MARGIN`-просрочки.
Точный баланс распределения. Голосовых/подписных/канистерных тестов нет. E2e через devnet: `create` →
выпуски по порядку по расписанию → `cancel`/`refund()`.
